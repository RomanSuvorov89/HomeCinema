# Контекст разработки HomeCinema

Репозиторий содержит исходники и воспроизводимую установку домашнего кинотеатра. Персональные конфиги, базы, токены, история и схема домашней сети в публичную документацию не включаются. Секреты создаются на целевом сервере или вводятся владельцем после установки.

## Состав

Lampac/Lampa, TorrServer, каталог рекомендаций и расписаний, дисковый кэш изображений. Есть Windows mpv bridge и инструкции Android. Основные исходники каталога — server/recommender, изображения — server/poster-cache, оформление — themes, установка — server и корневой install.sh.

Существующие отдельные контейнеры и новый общий Compose — разные способы установки. Обновления отдельных сервисов используют scripts/update-*.sh и не заменяют чужой Portainer stack. Смонтированный lampainit.js обновляется с сохранением inode и резервной копией.

## Реализованное поведение

- Профили через кнопку аватара, серверное состояние истории/настроек, переключение с перезагрузкой страницы, изоляция кешей и событий закладок.
- Apple TV оформление, прозрачные капсулы, сохранение оценок и фирменных цветов платформ, меню «Для меня» с исключением сериалов.
- Предзагрузка по реальному положению строк на экране с учётом контроллера items_line.
- Личная капсула оценки с корректными размерами. Интересные факты используют опубликованный текст Кинопоиска вместо CUB AI; при недоступности источника есть понятное сообщение и ссылка.
- Стрелка назад закрывает верхнее окно, возвращается по истории или заменяет единственную корневую карточку главной. Случай screens=1 подтверждён диагностическим логом и проверен после исправления.
- Расписания: Киноафиша как основной источник, Кинопоиск как резервный; сопоставление названия/года до импорта. Публичный ID Кинопоиска подключается отдельно от стабильного ID профиля HomeCinema.
- Изображения: точный путь TMDB через зеркала штатной Lampa, полный download без сохранения частичного ответа, дисковый кеш. Резервные постеры: сезон Киноафиши → основной Киноафиши → Кинопоиск. Метаданные сезонов кешируются отдельно, включая still_path для настоящих превью. Редирект Lampac сам по себе не подтверждает серверную загрузку изображения.

## Облако и переезд

Яндекс Диск без обязательного бота/VPS. Личное OAuth-приложение, device-code/QR, шифрование AES-GCM/scrypt, неизменяемые версии каждого сервера, проверка загрузки, предварительный просмотр и транзакционное восстановление с локальным backup. До выбора пользователя автосохранение выключено. Эпоха восстановления защищает серверный профиль от прежних снимков открытых вкладок. Поддерживаемые настройки устройств хранятся в зашифрованной копии; DNS-имена сервисов сохраняются.

Корневой install.sh устанавливает зависимости, скачивает проект, генерирует приватные конфиги и local_<hex> owner без фиктивного KP ID, проверяет порты, запускает четыре сервиса и health-check. Повтор скачивает актуальный коммит, сохраняет прежний Git ref и согласованный backup данных, обновляет сервисы без изменения личных настроек; при локальных правках исходников отказывается. Существующая раздельная установка получает обновление интеграции на месте, без замены Portainer stack. Первый вход предлагает облако; восстановленный каталог читается из SQLite сразу, импорт просыпается через Event. Инструкции: ONE_COMMAND.md, CLOUD.md и MIGRATION.md.

## Проверки и оставшиеся задачи

Обязательный запуск: bash scripts/check.sh. Сценарии оболочки проверены с имитацией пакетного менеджера/Docker; настоящий Python main/HTTP запущен на чистой временной базе. Полный прогон реальных контейнеров на новой ОС ещё нужен. Подключение Яндекс Диска подтверждено пользователем; восстановление реальной копии на отдельном сервере требует проверки.

Облако сейчас делает резервные копии, а не live-слияние двух независимых домов. Family Sync целого sync_view всё ещё имеет ограничения конфликтов. Не завершены: bridge после сна, перенос произвольных сторонних плагинов/авторизаций, полная проверка чистой установки и образов. См. TODO.md и KNOWN_ISSUES.md.

## Главная и личные списки

На главной остаётся заголовок «Главная» и его место в flex-разметке; удаляется только суффикс «- CUB». Пустая стрелка назад скрыта, в шапке также скрыта кнопка fullscreen (плеер не затронут). Названия «Сейчас смотрят»/«Из прошлых лет» без суффикса, генерируемые строки TV Series I Have Seen отбрасываются при обработке ответов, в том числе следующих страниц.

Штатный Watched сначала выбирает серию по таймлайнам и только затем читает online_watched_last. Наша подпись при наличии указателя использует именно последнюю выбранную серию; не исправляет/переписывает таймлайны и историю по максимальному номеру. Штатная конкурирующая подпись скрывается только у таких карточек, включая асинхронный рендер.

Штатный torrents.getFilterData использует общий torrents_filter как fallback, включая сезон. Обёртка оставляет общий quality/voice/lang и берёт сезон только из записи этой карточки с homecinema_scoped_season. Непомеченные старые сезоны очищаются при первом открытии, без удаления остальных настроек. Маркер хранится в torrents_filter_data, уже входящем в профиль/облако, но удаляется из результата getFilterData перед передачей штатному коду. Иначе selectedFilter перебирает его как неизвестный пункт и падает на filter_items[key][true]. Проверка использует настоящую функцию selectedFilter из upstream, а не только имитацию сохранения фильтра.

«Буду смотреть»: сервер объединяет KP watchlist и feedback want, исключает KP ratings и seen/not_interested; клиент добавляет native wath/scheduled, удаляет дубли и исключает native viewed и фильмы с прогрессом >=90%. Просмотр одной серии не завершает весь сериал. Главная и «Ещё» используют одну клиентскую политику. Это фильтрация домашнего списка, исходные записи и удалённый список КП не удаляются.

Для «Продолжить просмотр» сервер отдаёт series_releases из сохранённого episode_schedules, без запросов к внешним сайтам и без записи при GET. Клиент сопоставляет карточки по КП/TMDB ID либо уникальному оригинальному названию и году. Сериал исключается из этого ряда, если таймлайн последней вышедшей серии >=90%; один только online_watched_last завершение не доказывает. Если он указывает на другую серию, карточка остаётся — старая отметка финала не должна скрывать текущий просмотр/пересмотр. Неизвестное расписание и недосмотренная серия оставляют карточку. Кешированное расписание перестаёт доказывать завершение в день следующего релиза; новое расписание с непросмотренной серией возвращает сериал при следующем построении ряда. История и оценки сохраняются. Поздний ответ API и изменения таймлайна обновляют видимость уже построенных карточек только этого ряда.

Bootstrap до загрузки остальных плагинов подавляет только Noty.show для штатного plugins_add_success (и точной русской строки). Ошибки, параметры уведомлений и подтверждения действий проходят штатно. CSS скрывает только .head .halloween__button сезонной рекламы CUB Premium, включая позднюю вставку; остальные кнопки шапки и колокольчик сохранены.

Фильтрация по таймлайнам выполняется только при window.appready: наличие методов Timeline не означает, что native viewed уже прочитан. До ready карточки остаются, после app ready повторно проверяются уже построенные ряды «Буду смотреть» и «Продолжить»; обновления native timeline/profile read также обновляют видимость. Сами init/read истории наш фильтр не вызывает. test_timeline_startup.cjs запускает настоящий upstream-модуль из tests/fixtures/lampa-timeline.js, воспроизводит reading 754600950 до init, быстрый snapshot до ready, ready после init, частичный просмотр и чтение другого профиля.
