# Переезд и восстановление

## Быстрый путь с облачной копией

Для нового Linux-сервера используйте [установку одной командой](ONE_COMMAND.md), затем подключите прежний Яндекс Диск и восстановите копию. Начальный KP ID не требуется. Ниже описан полный файловый экспорт для переноса данных, которые не входят в облако, и точного отката.

## Что сохранить

Git восстанавливает программы и команды. Для переноса истории нужны отдельные данные Lampac, каталога, кэша постеров и TorrServer. Закладки, тайм-коды, рекомендации и настройки браузера не одно и то же: часть клиентских настроек остаётся в localStorage конкретного ТВ/браузера. Поддерживаемая часть уже сохраняется в профилях и облачных копиях; произвольные настройки сторонних плагинов требуют отдельного переноса.

Также сохраните фактические Docker-образы, если хотите воспроизвести ту же версию, а не будущий `latest`.

## Экспорт нынешних отдельных контейнеров

На сервере, из клона HomeCinema (можно выполнить из fish):

```sh
bash scripts/export-current.sh /home/YOUR_USER/homecinema-export
```

Замените YOUR_USER. Каталог должен быть пустым и находиться вне репозитория. Скрипт использует имена `lampac`, `kinopoisk-sync`, `roman-poster-cache`, `torrserver`; при других именах передайте переменные:

```sh
env LAMPAC_CONTAINER=lampac RECOMMENDER_CONTAINER=kinopoisk-sync POSTER_CONTAINER=roman-poster-cache TORRSERVER_CONTAINER=torrserver bash scripts/export-current.sh /path/to/export
```

Сначала проверяются контейнеры и mount TorrServer `/opt/ts`. Если у него другой путь, скрипт остановится до выключения сервисов: посмотрите `docker inspect torrserver` и сохраните реальный каталог настроек отдельно. Во время экспорта четыре сервиса временно останавливаются; после копирования прежние работающие контейнеры запускаются обратно, включая случай ошибки. Убедитесь, что команда завершилась успешно и контейнеры снова работают.

Экспорт содержит `server/data/...`, старый центральный JS для справки и список образов. Этот каталог **не загружать в Git**. Скопируйте его на внешний диск. Убедитесь, что получены базы и постеры:

```sh
find /path/to/export/server/data -type f
```

На текущем сервере дополнительно сохраните образы по одному:

```sh
docker inspect lampac --format '{{.Image}}'
docker inspect kinopoisk-sync --format '{{.Image}}'
docker inspect roman-poster-cache --format '{{.Image}}'
docker inspect torrserver --format '{{.Image}}'
```

Для каждого полученного SHA выполните `docker image save -o /external-disk/NAME-image.tar SHA`. После переезда `docker image load -i ...` вернёт образ; для использования именно его в Compose нужно указать соответствующий локальный tag вместо `latest`/`build`. Обычный установщик подтягивает текущий Lampac и пересобирает собственные сервисы, поэтому это отдельный способ точного отката.

## Новое место: восстановление экспорта

1. Подготовьте Linux, Docker и клон репозитория по README. Старые контейнеры на новом сервере не должны занимать порты нового Compose.
2. Заполните `config/stack.env` новыми LAN-адресами, `config/profiles.json` прежним ID Кинопоиска и **прежним** sync ID. Смена sync ID может создать другую область истории. Сохраните привычную шкалу оценок в `config/rating-scale.json`.
3. До первого запуска скопируйте экспортированные данные, находясь в корне нового клона:

```sh
mkdir -p server/data
cp -a /path/to/export/server/data/. server/data/
```

4. Восстановите владельца для двух сервисов, работающих от вашего UID:

```sh
sudo chown -R (id -u):(id -g) server/data/recommender server/data/poster-cache
```

Это синтаксис **fish**. Для bash: `sudo chown -R "$(id -u):$(id -g)" server/data/recommender server/data/poster-cache`. Скопированный Lampac `init.conf` просмотрите и замените старые LAN-адреса, если они там есть. Центральный JS будет заново сгенерирован, старый `lampainit.previous.js` для запуска не используется.

5. Запустите `bash server/install.sh`, затем `bash server/healthcheck.sh`. Если новая версия Lampac несовместима, используйте сохранённый образ и не продолжайте обновление вслепую.
6. На каждом устройстве откройте новый URL Lampac, полностью перезапустите приложение. Проверьте постеры, две последние просмотренные серии, запуск видео, звуковую дорожку и субтитры. Затем посмотрите новую серию и проверьте её отметку на втором устройстве.
7. На Windows обновите адрес через установщик bridge. Приложение ТВ, привязанное к старому серверу, может потребовать перенастройки/нового APK.

Старую установку и экспорт сохраняйте, пока эта проверка не пройдёт. Автоматизированный перенос реального экспорта ещё не проверен на новом компьютере.

## Резервная копия новой общей установки

```sh
bash server/backup.sh /external-disk/homecinema
```

Для восстановления в **новый пустой клон**, до запуска контейнеров:

```sh
tar -tzf /external-disk/homecinema/home-cinema-backup-DATE.tar.gz
tar -xzf /external-disk/homecinema/home-cinema-backup-DATE.tar.gz
```

Архив создаётся нашим backup.sh и содержит `server/data`, `.runtime.env`, конфигурацию и VERSION; код берётся из Git. При необходимости используйте соответствующий прошлый коммит. Перед запуском исправьте LAN-адреса, владельцев данных и заново выполните установщик. Не распаковывайте поверх работающих SQLite.

Независимые сервисы вроде reverse proxy, VPN/прокси, qBittorrent и других домашних приложений не включены в этот Compose. Если для доступа к источникам необходим ваш прокси, перенесите его конфигурацию отдельно.
