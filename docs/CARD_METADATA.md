# Открытие информационных карточек

Для «Нулевого пациента» (TMDB 154598, КП 4642708) подтверждены два уровня
блокировки CUB: ID присутствует в клиентском `/blocked`, а запрос описания
`3/tv/154598` возвращает `blocked: true` вместо метаданных. Прямой TMDB отдаёт
описание, один сезон и семь серий. Перезапуск Docker эту причину не устраняет.

Центральный bootstrap HomeCinema включает штатный `disable_features.dmca`
и открывает публичный `Utils.dcma` для информационных карточек. Это работает
при ранней и поздней загрузке, в том числе после запоздавшего ответа `/blocked`.
Если штатный `Api.full` получает `movie.blocked`, он один раз вызывает
штатный загрузчик TMDB с теми же ID и типом. ID КП сохраняется из исходной карточки.
Обычные ответы и сетевые ошибки исходного каталога проходят прежним путём.
Неудачная резервная загрузка завершается ошибкой максимум через 20 секунд.

Кэш постеров теперь также сохраняет публичные метаданные TMDB по фиксированным
маршрутам `/tmdb/metadata/{tv|movie|collection}/{id}` и ограниченному набору
разделов карточки. Сезоны используют прежний `/tmdb/season/`.
Запросы идут только на `api.themoviedb.org` через уже используемый DoH;
пользовательский URL не принимается. Ключ API берётся из штатного запроса Lampa,
не входит в имя кеша и не выводится в журнал; дисковый кеш хранит только JSON
описания. Рабочие копии используются при временной недоступности TMDB.

Клиент включает маршрут метаданных только если `/index.json` сообщает
`metadata_cards: true`: обновление одного плагина не перенаправляет запросы
на отсутствующий маршрут старого кэша. Полное обновление HomeCinema пересобирает
кэш вместе с клиентом. Старые сценарии обновления кэша также копируют новый модуль
и Dockerfile. Настройка находится в `lampainit.js`, поскольку фоновые обновления
интерфейса Lampac могут переписывать HTML.

После обновления полностью перезапустите Lampa на ТВ; в браузере нажмите Ctrl+F5.

Проверки: полный `bash scripts/check.sh` прошёл в чистой временной копии;
для него использовался временный Linux Node.js 22 и установленный в контейнере
пакет qrcode без изменения системных пакетов Ubuntu. Регрессия выполняет настоящие
функции Lampa, воспроизводит ранний отказ и серверный blocked-ответ, проверяет
поздний список, повторную установку, ID, детский режим и ограничение времени ошибки.
Проверены валидация маршрутов, отказ при неверном ID/ответе, дисковый кеш,
восстановление после перезапуска, CORS и отсутствие ключа в журнале/файлах.

На действующей установке проверены настоящий blocked-ответ CUB и резервный
штатный загрузчик из реально отданного app.min.js/lampainit.js: получены
«Нулевой пациент», семь серий и 25 актёров через локальный кэш. Проверка сервисов
прошла. Визуальная проверка Яндекс Браузера недоступна в среде автоматизации;
воспроизведение видео и конкретный телевизор этим прогоном не проверялись.
