# TMDB: DNS и маршрут до изображений

## Что подтверждено диагностикой 21 октября 2026

- Пользователь сообщил, что изображения работали напрямую и пропали примерно за неделю до диагностики. Правило Podkop добавлялось только в день проверки; нельзя считать его причиной первоначального сбоя.
- Системное разрешение имён TMDB возвращало loopback. Google DoH также возвращал loopback для CDN-алиаса; Cloudflare DoH возвращал публичные адреса.
- API по публичному адресу с правильным TLS-именем отвечал 401 без ключа — соединение работало.
- Один и тот же публичный адрес картинки не отвечал напрямую с Windows и CachyOS, но через уже настроенный интерфейс awg0 на OpenWrt возвращал 200 image/jpeg.
- Пользователь подтвердил открытие исходного URL постера в браузере после добавления правила. Изменённый URL давал 404; это не доказывает недоступность исходного URL или источник ответа.
- В текущем текстовом списке обнаружен tmdb.com. Он не охватывает image.tmdb.org и api.themoviedb.org. Domain Resolver выбранной VPN-секции был выключен.

Точная причина изменения прямой доступности неделю назад не установлена. Открытие локальной панели при домене TMDB согласуется с неверным разрешением имени, но точный путь до панели отдельно не подтверждён. Ответ браузера 499 antivirus относится к конкретному запросу Windows и не объясняет всю домашнюю сеть.

## Сначала диагностика, без изменений

На официальном форуме TMDB администратор Travis Bell 29 апреля 2024 объяснил, что ответ 127.0.0.1 означает распознавание клиента как находящегося в России или Беларуси: https://www.themoviedb.org/talk/662ca47903bf840122ea3636?language=af-ZA . Это документированный механизм ограничения на стороне сервиса, а не доказательство ошибочного домашнего DNS. Разница ответов рекурсивных резолверов сама по себе не означает, что они настроены неверно.

Google DoH в пользовательской диагностике возвращал loopback и Comment `Response from 91.200.176.1.`. Этот Comment указывает на ответ авторитетного сервера в цепочке разрешения; сравнение с отключённым ECS позволит проверить влияние клиентской подсети. Историческая причина ухудшения именно неделю назад не установлена.

`scripts/diagnose-tmdb.sh` запускается через `sh` на CachyOS и OpenWrt. Он только читает: hosts, DNS, слушателей 80/443, контейнеры на 443, отдельные несекретные параметры роутера; запрашивает Google DoH по умолчанию и без ECS, Cloudflare; сравнивает TLS через системный DNS и явный loopback; получает заголовки локального HTTP с Host TMDB. Настройки, файлы конфигурации, маршруты и службы не меняет, сертификаты не отключает. Прокси окружения для этих контрольных запросов обходятся, поэтому результат не следует автоматически переносить на браузер.

Для CachyOS проверяется гипотеза: loopback ведёт в локальный Nginx Proxy Manager на порту 443, который отвергает неизвестный SNI. Для OpenWrt проверяются локальные слушатели и HTTP-ответ. Даже совпадающий ответ локального сервера не доказывает полный путь конкретного запроса браузера; при необходимости понадобятся его peer address или трасса соединения.

## Отклонённый обход

Пользователь отклонил преждевременное изменение VPN/DNS. `fix-podkop-tmdb.sh` и его тест удалены из активного набора; прежняя версия есть в истории Git, но не рекомендуется к запуску. Никаких новых настроек, прокси, правил маршрутизации или перезапусков в этом диагностическом обновлении нет.

Правила OpenWrt не начинают автоматически действовать на сервер выше него за MikroTik. Тайм-аут CDN при прямом соединении и 200 JPEG через awg0 — подтверждённая разница путей, но она не устанавливает конкретный механизм сетевой фильтрации или дату изменения.

## Уточнение по рабочей Lampa и Lampac

Позднее пользователь показал включённое проксирование в отдельной Lampa TV и подтвердил: в Lampac фон загрузился после включения плагина и проксирования. Контрольный Image в браузере успешно загрузил 300×450 через `/tmdb/img/t/p/w300/...jpg?uid=...`. Это опровергает обобщённый вывод о неработоспособности endpoint Lampac и обязательности VPN для приложения. Прямые сетевые проверки описывают только прямой путь. Для приложения используется проверенный Lampac; кэш 0.3.0 сохраняет его изображения. Возможность загрузки из самого контейнера проверяется отдельно при обновлении, до активации клиента.
