# Облачное сохранение через Яндекс Диск

HomeCinema сам обращается к Яндекс Диску. Бота, VPS, отдельного публичного сайта, входящих портов и подписки HomeCinema нет. Используется место вашего Диска. Работа дома не зависит от доступности облака.

## Первое подключение

1. Откройте [Яндекс OAuth](https://oauth.yandex.ru/) под своим аккаунтом и создайте приложение HomeCinema. Дайте ему только право **«Доступ к папке приложения на Диске»** (`cloud_api:disk.app_folder`). Если форма требует Redirect URI, используйте официальный `https://oauth.yandex.ru/verification_code`; наш вход использует device-code, а не локальный callback. Если Яндекс требует модерацию для выбранного приложения, завершите её: код не обходит ограничения провайдера.
2. Сохраните **ClientID и Client secret** из карточки приложения в менеджере паролей. При переезде используйте **то же приложение**: папка приложения зависит от ClientID. Не присылайте secret в чат и не добавляйте его в Git.
3. Откройте Lampa → **R → Облачное сохранение → Подключить Яндекс Диск**. Введите ClientID и secret один раз. Пароль Яндекса HomeCinema не запрашивает.
4. Сканируйте QR (он содержит официальный адрес `https://oauth.yandex.ru/device`), введите показанный рядом код на странице Яндекса и разрешите доступ. HomeCinema проверяет результат с интервалом, заданным Яндексом. Код ограничен по времени.
5. Для первой установки выберите **«Начать новое облачное сохранение»**. Ключ создаётся автоматически и сохраняется в папке приложения на Диске; отдельный пароль не нужен. Не выбирайте этот пункт вместо восстановления существующих данных.
6. Дождитесь сообщения об успешной копии и времени сохранения в меню. Для подключения уже существующего дома выбирайте восстановление, а не начало нового сохранения.

Само создание OAuth-приложения нельзя выполнить незаметно из установщика: приложение и разрешения принадлежат пользователю Яндекса. Client secret хранится только на вашем сервере. Обычная экранная клавиатура Lampa пишет ввод в console.log, поэтому для secret и пароля старой копии используется отдельное поле password без этой клавиатуры и без сохранения введённого текста в localStorage. На конкретных телевизорах ввод секретов ещё требует проверки; первоначальную настройку проще выполнить на ПК.

## Что сохраняется

- Профили HomeCinema, их имена, доступная на сервере история/избранное, тайм-коды `file_view`, последняя серия, личные настройки и тема.
- Оценки и «Буду смотреть», «Не интересно», предпочтения дорожек, состояния отслеживания сериалов, расписания и метаданные из поддерживаемых таблиц каталога.
- Подключённые публичные ID Кинопоиска по профилям.
- Настройки известных устройств: DNS-адрес TorrServer, режим ссылки и его реквизиты, адрес/ключ парсера, громкость, качество, субтитры и оформление. Они лежат внутри зашифрованного файла. На новом устройстве без совпадающего ID применяется последний сохранённый набор; настройки можно изменить после восстановления. При обычной работе настройки ПК и ТВ друг друга не заменяют.

Ранее закрытое устройство должно хотя бы раз открыть обновлённую Lampa, чтобы его локальная история попала на сервер. Полный список поддерживаемых полей — `profiles.SETTINGS/HISTORY` и `cloud_disk.DEVICE_FIELDS`. Произвольные настройки сторонних плагинов, их cookie/авторизации, OAuth-сессия Яндекса, Docker Compose/.env, двоичные файлы и дисковый кэш изображений **в эту копию не входят**. Полный перенос инфраструктуры описан в [MIGRATION.md](MIGRATION.md). Настройки новых внешних плагинов добавляются явно, а не выгружаются вслепую вместе с токенами.

## Автоматическая синхронизация

Сервер обращается к Диску **раз в час**, читает список версий и скачивает ещё не обработанные версии. Интервал и результат проверки сохраняются между перезапусками. Кнопка «Синхронизировать сейчас» запускает этот же цикл вручную, сначала отправляя актуальное состояние открытого клиента на домашний сервер.

Сравниваются личные данные, а не байты всей SQLite: темы, настройки, история, избранное, оценки, списки, подключённый ID КП и предпочтения дорожек. Номера ревизий профиля, время фоновой проверки, обновления метаданных/постеров/рекомендаций и кеш расписания не считаются изменением пользователя. Если объединённое состояние уже есть в облаке, новый файл не создаётся, включая ручной запуск. Интерфейс сообщает «Настройки актуальны — новая версия не создавалась».

ПК и ТВ отправляют изменения в локальный модуль профилей сразу, не ожидая облачного часа. На сервере они объединяются относительно базы каждого клиента. Просмотры разных фильмов/серий имеют разные ключи и сохраняются вместе. Облачный слой также объединяет отдельные записи с устойчивыми часами изменения и отметками удаления, а не выбирает целиком последний снимок. Для одной серии используется её `updated` / `_hc_updated`: поздний повторный просмотр с меньшим процентом не превращается в старый просмотр только из-за процента. При одновременном изменении одной обычной настройки на независимых серверах выбирается более поздняя запись; при равном времени порядок стабилен по счётчику и ID сервера. Часы ОС должны быть корректными.

Отдельные настройки устройств объединяются по ID устройства: громкость/плеер ПК не заменяют настройки ТВ. Удалённые записи не возвращаются от старого сервера без нового явного изменения. Категории избранного объединяются по членству карточек. Смена владельца при переносе нормализуется; ID остальных профилей сохраняются.

Два независимых сервера могут одновременно загрузить разные неизменяемые файлы: имена содержат ID сервера, перезаписи общего файла нет. На следующем часовом цикле прочитываются обе версии и объединяются изменения. Локальная запись, пришедшая во время скачивания, включается в транзакцию до применения облака. Клиенты, ожидающие SQLite-записи, продолжают работу после неё. Фоновое слияние не сбрасывает эпоху профилей и не требует перезагрузки всех устройств.

Активный клиент HomeCinema отключает старые Family Sync/bookmark/timecode плагины, чтобы они параллельно не возвращали целые устаревшие снимки. После обновления нужны Ctrl+F5 / полный перезапуск каждого ТВ. Нативная история Lampa и её обработчики остаются; модуль профилей обновляет память Timeline после импорта.

На Диске `app:/HomeCinema` остаются **3 последние версии каждого сервера** для отката, а не по файлу каждые пять минут. Более старые версии этого сервера перемещаются в корзину только после подтверждённой записи новой; чужие серверы и файлы ключей не удаляются. Существующие лишние версии сокращаются при следующей реальной публикации. Корзина Диска управляется средствами Яндекса.

Формат файла остаётся `hc-TIMESTAMP-INSTANCE.hcb`. Новые HCLOUD2 шифруются AES-256-GCM случайным ключом из отдельного `key-ID.json` в приватной папке приложения. Авторизация Яндекса открывает доступ и к ключу, и к данным; отдельный пароль не нужен, защиты от самого провайдера этот вариант не даёт. Файлы ключей не удаляйте — они нужны версиям отката. Старые HCLOUD1 с scrypt доступны для ручного восстановления с прежним паролем. Максимальный размер распакованной версии — 64 МБ.

Старые полные копии без записей синхронизации читаются по последней доступной версии каждого сервера. После первого слияния часы и сравнение сохраняются локально; первый запуск без изменений не публикует дубликат. Старые HCLOUD1, ключа которых нет на данном сервере, требуют ручного восстановления с паролем; неизвестный пароль не обходится.

При сетевой ошибке локальные данные остаются, повтор будет в следующем часовом цикле или по ручной кнопке. Счётчики и изменения сохраняются до повторной попытки. Refresh token обновляет OAuth при истечении; при отзыве доступа потребуется повторное подключение. Подключение нового Диска само по себе не начинает запись и очищает прежнюю локальную базу сравнения.

## Переезд и восстановление

1. На старом сервере откройте актуальные клиенты, выберите «Синхронизировать сейчас» и дождитесь подтверждения.
2. Разверните HomeCinema [одной командой](ONE_COMMAND.md) на новом сервере; начальный ID Кинопоиска больше не требуется. DNS-имена TorrServer могут остаться прежними — настройте их разрешение на новом роутере.
3. Подключите тот же Яндекс Диск, используя **тот же ClientID/secret**. Автосохранение пока выключено: пустая установка не публикует свои данные автоматически.
4. Выберите версию. Для новой копии ключ загрузится автоматически после авторизации. Только для старой копии HCLOUD1 понадобится её прежний пароль. Проверьте показанные дату, число профилей и оценок. Подтвердите восстановление.
5. До замены создаётся локальная SQLite-копия `data/cloud/before-restore/`. Данные импортируются одной транзакцией; несовместимая схема/нарушенные связи отклоняются. SQL из архива не исполняется. При другом основном ID профиля записи владельца переносятся на ID новой установки.
6. Страница перезагрузится. Остальные ТВ/вкладки тоже полностью перезапустите. Новая эпоха восстановления не даёт старым вкладкам сохранить прежние снимки профилей поверх восстановленных; при перезагрузке они сначала получают серверное состояние.

Необновлённые самостоятельные клиенты Lampac/Family Sync могут иметь отдельные хранилища: обновите и перезапустите все устройства перед проверкой. Для восстановления поверх уже используемой установки заранее закройте остальные клиенты; облачная копия профилей не является резервной копией всех SQLite Lampac.

## Кинопоиск в меню R

**R → Подключённые сервисы — Кинопоиск → ID или ссылка на профиль**. Стабильный ID HomeCinema не меняется при смене источника оценок. Поддерживаются числовой ID и `https://www.kinopoisk.ru/user/ID/`. Сохранение запускает фоновый импорт публичных оценок и «Буду смотреть» в выбранный профиль, штатный цикл также обновляет подключённые профили. При недоступности/закрытости профиля старые оценки остаются. Существующие ограничения рекомендаций вторичных профилей пока сохраняются; ввод ID не является полноценным входом на Кинопоиск.

## Обновление действующей установки

Из fish через SSH: скачайте `scripts/update-cloud.sh` по полному SHA коммита и выполните `bash /tmp/update-cloud.sh SHA`. По умолчанию используется существующий каталог `/home/romans/kinopoisk-sync`, центральный JS и кэш изображений; пути можно передать аргументами как у update-profiles.sh. Делается резервная копия, собирается только текущий сервис каталога, выполняются тесты профилей/облака, затем устанавливается центральный JS с сохранением inode. Lampac только перезапускается, его Portainer stack не заменяется.

Зависимости: cryptography 46.0.3, qrcode 8.2 (зафиксированы в requirements-cloud.txt). Для локальной проверки: `python3 -m pip install -r server/recommender/requirements-cloud.txt`, затем `bash scripts/check.sh`.

Подключение предназначено для доверенной домашней сети. Облачные операции отвергают чужой browser Origin; secret/token/ключ не возвращаются в status, запросы с секретами не логируются. Локальные служебные файлы имеют права 0600. Это не новый слой авторизации публичного Lampac: не публикуйте незащищённый API каталога в интернете.

## Проверено и что ещё проверить

Проверены шифрование/неверный пароль/подмена файла, device flow и интервал опроса, отсутствие токенов в статусе и снимке, загрузка с проверкой целостности, восстановление оценок/настроек и перенос owner ID, откат транзакции, резервная копия перед заменой и отказ старому клиенту. Яндекс заменён детерминированным API-стендом; настоящий OAuth/Диск, Docker-сборка и ввод на телевизорах в этой среде не проверены. После установки сначала проверяются подключение, внеочередная копия и восстановление на отдельной тестовой базе, а не замена рабочей истории ради проверки.

Документация протоколов: [device-code Яндекса](https://yandex.ru/dev/id/doc/en/codes/screen-code-oauth), [API Диска](https://yandex.ru/dev/disk/rest/).

Проверка часовой синхронизации использует две независимые настоящие SQLite-базы и имитацию транспорта Диска: одновременные публикации, ПК/ТВ в одном часе, повторный просмотр, удаления, оценки/КП, настройки устройств, изменение во время скачивания, перезапуск, служебные ревизии и отсутствие циклических одинаковых загрузок. Настоящий Яндекс, длительный часовой прогон и устройства пользователя ещё требуют подтверждения.
