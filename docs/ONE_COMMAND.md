# Установка и обновление одной командой

На новом или уже настроенном Linux-сервере с интернетом и systemd (Debian/Ubuntu или Arch/CachyOS), из bash или fish:

```sh
bash -c 'f=$(mktemp) && curl -fSL https://raw.githubusercontent.com/RomanSuvorov89/HomeCinema/main/install.sh -o "$f" && bash "$f"; r=$?; test -z "${f:-}" || rm -f "$f"; exit "$r"'
```

Для этой стартовой команды уже нужны bash и curl. Остальные зависимости установщик поставит сам; при работе обычным пользователем понадобится sudo и, возможно, пароль Linux. Программа скачивается из нашего публичного GitHub, секреты туда не отправляются.

## Что произойдёт

1. Установщик проверит/поставит Git, Python, curl, Docker и Compose; запустит Docker.
2. Скачает HomeCinema в `$HOME/HomeCinema`. Другой путь задаётся `HC_INSTALL_DIR`.
3. Определит IPv4 сервера, создаст приватные настройки, случайный пароль Lampac и sync ID. Пароли/профили не печатаются в терминал. Основной профиль — локальный, без выдуманного ID Кинопоиска.
4. Проверит порты 9118/8090/9120/9121. Если они заняты другим стеком или программой, остановится; не будет удалять контейнеры или останавливать чужие сервисы.
5. Сгенерирует центральный клиент с нашими профилями, темой, предзагрузкой, изображениями и исправлениями. Развернёт Lampac, TorrServer, каталог и кэш изображений; проверит доступность сервисов.
6. Выведет адрес Lampa. При первом открытии появится меню облачного сохранения.

Вручную копировать примеры конфигов, вводить начальный ID КП или выполнять отдельные команды запуска не требуется. Повторный запуск этой же команды скачивает актуальный `main`, сохраняет предыдущую версию кода в `refs/homecinema/backups/<дата>`, создаёт приватный согласованный архив данных через `server/backup.sh` и переключает код на скачанный коммит. Затем пересобирает собственные сервисы, обновляет образы Lampac/TorrServer, генерирует клиент и проверяет доступность. На время согласованного backup работающие сервисы кратко останавливаются и запускаются обратно. Адреса, пароли, DNS-имена, профили и базы сохраняются. После обновления на ПК нужен Ctrl+F5, на ТВ — полный перезапуск Lampa.

Если возвращаетесь в старый дом через полгода, достаточно той же команды. Для другого каталога установки повторно задайте прежний `HC_INSTALL_DIR`. Для конкретной версии вместо main можно задать `HC_REF=<полный SHA>`. Установщик не перезаписывает изменённые отслеживаемые исходники: при локальной правке останавливается с объяснением; незакоммиченная работа сохраняется. Ошибка скачивания не запускает обновление сервисов. Ошибки сборки/запуска не скрываются; автоматического отката схем баз нет — прежний код и архив данных сохраняются для согласованного восстановления. Архивы находятся в `server/backups`, содержат личные данные и могут занимать место: переносите нужные копии на внешний диск.

При обнаружении прежней раздельной установки (`$HOME/kinopoisk-sync/kp_sync.py` и `$HOME/lampac/plugins/lampainit.js`) и отсутствии конфигурации объединённого стека команда запускает обновление каталога/профилей и центрального клиента на месте. Этот путь делает SQLite backups и проверки нового образа до активации; сохраняет inode центрального JS. Существующий Portainer stack и TorrServer не заменяются, второй комплект контейнеров не создаётся. Это обновление интеграции существующих сервисов, а не автоматическая конвертация в общий Compose. Нестандартные пути задаются `HC_LEGACY_DIR`, `HC_LAMPAINIT`, `HC_POSTER_DIR`; каталог poster-cache необязателен.

## Восстановление своего дома

Откройте выведенный URL на ПК или ТВ. В меню Яндекс Диска укажите **тот же ClientID и Client secret**, которыми пользуетесь сейчас; подтвердите вход по QR/коду, выберите копию. Ключ новой копии загрузится автоматически; пароль нужен только для старого формата HCLOUD1. Не создавайте новое OAuth-приложение для каждого дома: папки разных приложений различаются.

Эти подтверждения нельзя выполнить автоматически без ваших учётных данных. Секреты вводятся в интерфейсе, а не в команду и shell history. До выбора восстановления или нового сохранения автоматическая запись на Диск выключена.

После восстановления текущие профили/история/оценки/темы/поддерживаемые настройки и источник КП берутся из копии. Основной профиль новой установки имеет стабильный локальный ID, к нему переназначаются записи прежнего владельца. Настоящий ID КП хранится отдельно в home_connections; фоновый импорт просыпается после восстановления. Данные профиля доступны из SQLite сразу, без ожидания скачивания всех оценок заново. Картинки догружаются по мере использования.

Проверьте выбранный профиль, последнюю просмотренную серию и запуск видео; затем откройте Lampa на остальных устройствах. Windows bridge устанавливается на соответствующий ПК отдельно. Состав копии и ограничения — [CLOUD.md](CLOUD.md).

## Свои DNS-имена

Если хотите сразу использовать настроенное на роутере имя вместо автоматически выбранного IP:

```sh
# Выполните стартовую команду выше с переменной перед ней:
env HC_PUBLIC_HOST=cinema.home bash -c 'f=$(mktemp) && curl -fSL https://raw.githubusercontent.com/RomanSuvorov89/HomeCinema/main/install.sh -o "$f" && bash "$f"; r=$?; test -z "${f:-}" || rm -f "$f"; exit "$r"'
```

Само имя должно уже разрешаться на новый сервер с ПК и телевизоров. Настройки роутера установщик не меняет. Сохранённый в облаке DNS-адрес TorrServer переносится как есть; начальные defaults не перезаписывают восстановленный адрес. При нескольких сетевых интерфейсах/VPN при необходимости задайте HC_PUBLIC_HOST явно.

## Проверки и границы

Локально проверено обновление с настоящими Git clone/fetch/checkout и переходом между двумя версиями: приватные настройки и история сохранены, прежний коммит доступен, локальные правки блокируют обновление, прежняя раздельная установка выбирает свой путь. Пакетный менеджер и Docker в этом тесте не запускаются. Также проверены: генерация приватных конфигов без KP ID, повторный запуск с сохранением данных/секретов, отказ при чужом занятом порте, распознавание собственного Compose, прохождение полного shell-сценария с имитацией пакетного менеджера/Docker и запуск **настоящего Python-сервера** на новой базе с локальным владельцем. Доступны профили, пустой каталог, подключение КП и статус первого восстановления.

Установка пакетов на чистой ОС, загрузка реальных Docker-образов, настоящий старт всех четырёх контейнеров и восстановление через Яндекс на новом ПК пока не проверены. Тестовый shell-прогон не доказывает совместимость конкретной будущей ОС/версии Lampac. При ошибке установщик завершится с её выводом; существующие домашние сервисы не удаляются.

Это установщик **комплекта HomeCinema**, а не всех домашних приложений. Immich, Home Assistant, WorkCalendarSync, qBittorrent, настройки VPN и роутера имеют собственные установки/экспорты.

При чистом запуске Windows/WSL подтверждено: API /version работает, но главная возвращает HTTP 500 из-за отсутствующего wwwroot/lampa-main. Архив нужной версии доступен через codeload из контейнера; точная причина сбоя фонового загрузчика Lampac пока не установлена. Установщик теперь заранее скачивает и проверяет UI (версия из ModInit.cs образа, с закреплённым резервным ref), добавляет /lampainit.js как штатный LampaCron и сохраняет UI в server/data/lampac/lampa-main через bind mount. При ошибке скачивания/архива прежний UI сохраняется, установка завершается ошибкой. Health проверяет HTML, app.min.js, CSS и lampainit.js вместо одного /version. Автотесты используют ZIP-фикстуры и локальный HTTP-сервер; применение на WSL требует подтверждения.
