# Кэш изображений и данных сезонов 0.3.2

Основной источник — изображения TMDB через зеркала штатной Lampa: `nl.imagetmdb.com`, затем `de.imagetmdb.com`. Оба проверены из контейнера пользователя: 200 JPEG, полный размер 46564 байта. Прямой `imagetmdb.com` в список не включён: у пользователя загрузка оборвалась на 20508 байтах. Клиент направляет в дисковый кэш исходные постеры, фоны, постеры сезонов и кадры серий. Для известного `poster_path` первым загружается именно TMDB; постер Киноафиши больше не заменяет его принудительно.

Если путь TMDB отсутствует или загрузка завершилась ошибкой, для постера используется прежняя цепочка: Киноафиша (сезон → основной постер) → Кинопоиск. Сохранённые запасные постеры остаются. Для недоступного кадра серии может показываться постер сезона с явной подсказкой; он не выдаётся за настоящий кадр. Битый декоративный фон скрывается. Ожидание загрузки больше не прерывается произвольным таймером на 7 секунд.

## Сохранение TMDB

`/tmdb/image/t/p/SIZE/HASH.jpg` принимает только путь изображения, не произвольный URL. Сервер обращается к фиксированным зеркалам с тем же точным путём изображения. UID и семейный токен зеркалам не передаются. Загрузка и перенаправления разрешены только по HTTPS с проверкой сертификата. При ошибке или неполном файле первое зеркало отбрасывается, проверяется второе. Если оба недоступны, клиент переходит к резервному постеру.

`LAMPAC_URL` остаётся источником каталога закладок, но больше не участвует в скачивании изображений. Проверка из контейнера показала: `/tmdb/img/` возвращает 302 на прямой TMDB при ошибке серверной загрузки. Успех Image в браузере показывал исходный src и не доказывал серверную загрузку.

Файлы находятся в `data/posters/tmdb` (в общей установке — `server/data/poster-cache/posters/tmdb`). Ключ включает путь и размер: разные кадры/разрешения не смешиваются. Успешное изображение с тем же hash-путём сохраняется без срока истечения; новый путь TMDB создаёт новый файл. Повторные запросы и перезапуск сервиса используют диск, даже при недоступности внешней сети. Это кэш по мере просмотра, а не предварительное скачивание всего каталога.

Перед сохранением проверяются HTTP-успех, ограничение размера 8 МБ и сигнатура полного JPEG/PNG/WebP. HTML-ошибки не сохраняются. Запись атомарная; одновременные запросы одного файла объединяются. После неудачи повторная загрузка ограничена на 60 секунд. В HTTP используются ETag/304 и immutable-кэш.

При первом запуске нового клиента включаются `proxy_tmdb` и `proxy_tmdb_auto`, далее ручной выбор не перезаписывается. Обработчик изображений направляет точный TMDB-путь в кэш и восстанавливает обёртку после поздней загрузки TMDB Proxy. `src` и `data-src` согласованы с lazy render Lampa. Обработчик API меняется только для запросов tv/ID/season/N: они идут в локальный кэш сезонов. Остальные методы используют прежний обработчик.

## Обновление действующей установки

`bash scripts/update-series-assets.sh COMMIT_SHA [POSTER_DIR] [CATALOG_DIR] [LAMPAINIT]` обновляет сервер и встроенный клиент с копиями, пересобирает существующий poster-cache, проверяет версию/endpoint дат и реальное сохранение контрольного изображения с зеркала внутри контейнера. Только после успешной проверки устанавливает клиент, восстанавливает порядок профилей и перезапускает Lampac. При ошибке проверки новый клиент не подключается; старые данные и копии исходников остаются. Portainer stack не пересоздаётся.

После установки полностью перезапустите Lampa на ТВ / Ctrl+F5 на ПК. `curl http://SERVER:9121/health` показывает `version: 0.3.2` и `tmdb_saved`. Логи новых файлов: `tmdb saved: t/p/...`. Запасные постеры: `poster saved: ... source: kinoafisha-season`, `kinoafisha-main` или `kinopoisk`.

Автоматически проверены приоритет источников, отсутствие замены успешного TMDB, точные кадры, поздняя загрузка плагина, переключение зеркал при обрыве/HTML, перезапуск/офлайн, одновременные запросы, разные размеры, HTML-ошибки, строгие пути и HTTP-кэш. Доступ к двум зеркалам из контейнера пользователь подтвердил. Сохранение через обновлённый кэш и отображение на ПК/ТВ проверяются установщиком и пользователем.

## Резервные постеры и даты

Точные соответствия KP/TMDB/IMDb/путей собираются из каталога и закладок. Неоднозначные соответствия не используются. Киноафиша проверяет название/год. Сезон запасного постера берётся из season_number, последней серии или расписания. `poster-overrides.json` и старые `.img`/`.v3.sN.img` сохраняются. Запасные постеры Киноафиши проверяются через сутки, КП через 6 часов; при ошибках обновления остаётся сохранённый файл.

`/series/kp/ID.json` читает публичные номера/даты из episode_schedules в SQLite в режиме mode=ro, не запускает парсинг. Уже известная нативная дата сохраняется. Монтирование каталога rw нужно для SQLite WAL sidecar-файлов, запросы остаются read-only.

## Только для существующей отдельной установки

Этот способ не нужен при использовании общего server/docker-compose.yml. Он сохраняет старое имя контейнера `roman-poster-cache`, чтобы не менять привычные команды диагностики.

```sh
cd server/poster-cache
cp config.env.example .env
```

В `.env` укажите доступные телевизорам POSTER_BASE/LAMPAC_URL, настоящий каталог баз CATALOG_DIR, путь LAMPAINIT и текущий семейный токен. Вместо localhost нужен LAN-адрес сервера. Затем:

```sh
bash install.sh
```

Перед изменением центрального JS установщик проверяет загрузку изображения, сохраняет резервную копию, сохраняет inode bind mount и перезапускает контейнер `lampac`. Сервисы не должны одновременно использовать порт общей установки.

Диагностика: `docker logs --tail 60 roman-poster-cache`, `curl -fsS http://SERVER_IP:9121/health`. Поле `catalog_errors` должно быть пустым после прогрева. `/index.json` содержит точные соответствия ID/путей. Кэш на диске сохраняется при `docker compose down`.

Для удаления только дополнения: `bash uninstall.sh`. Файлы изображений остаются на диске. После изменения полностью перезапустите Lampa либо Ctrl+F5 в браузере.

## Адреса кадров серий

Изображения не появятся без `still_path` из API сезона. Пользователь подтвердил: Lampac /tmdb/api/3/tv/ID/season/N сбрасывает соединение; прямой TMDB API с Cloudflare DoH из контейнера возвращает все 8 серий с кадрами. Поэтому 0.3.2 направляет только запросы сезонов в `/tmdb/season/ID/N.json`, затем сервер получает публичные метаданные с api.themoviedb.org через DoH. Сами кадры по их точным путям сохраняются через проверенные NL/DE зеркала.

Метаданные по сериалу/сезону/языку сохраняются в `data/posters/tmdb-seasons` на 6 часов. При сетевой ошибке остаются ранее сохранённые данные. Ответы с ошибкой и неполный JSON не записываются. Параллельные запросы объединяются, после ошибки действует пауза 60 секунд. API-ключ поступает от штатной Lampa в запросе, проверяется и используется только для загрузки; в имени кэша/содержимом и логах запросов он не сохраняется. Домашний DNS не меняется. Поле health `tmdb_seasons_saved` показывает количество сохранённых сезонов.

Установщик поддерживает дополнительную проверку: `TMDB_API_KEY=YOUR_LAMPA_TMDB_KEY bash scripts/update-series-assets.sh COMMIT_SHA`. Ключ передаётся только в окружении запуска, не сохраняется в .env или Git. Перед активацией клиента проверяются реальный ответ сезона и сохранение одного настоящего кадра. Без этой переменной остаётся обязательная проверка постера. После обновления закройте список файлов и откройте его заново; на ПК Ctrl+F5, на ТВ полный перезапуск приложения.
