# Home cache 0.6.0

Цель: открытие главной не запускает подготовку рекомендаций и поиск карточек.
Это подготовленное сервером представление данных (read model), независимо от
доступности и полноты интеграции с публичным профилем Кинопоиска.

## Что хранится

`/data/home-cache.sqlite3` — отдельная SQLite с WAL. Не заменяет и не сбрасывает
recommender.sqlite3, её media/features/user_ratings и прочие таблицы.
Фильмы и сериалы хранятся в одной cards с явным media_type: это одна сущность
с одинаковым набором базовых полей; раздельные таблицы не ускорят главную.

| Таблица | Ключ | Данные/связь |
|---|---|---|
| cards | source:type:catalog_id | Полный JSON карточки каталога, source, media_type, catalog_id, refreshed_at |
| identity_links | kp_id, media_type | Ссылка card_key на cards, время подтверждения сопоставления |
| shelves | profile_id, kind | Название и время последней успешно опубликованной группы |
| shelf_items | profile_id, kind, position | Ссылка cards + extra_json с прогнозом/данными конкретного профиля |
| worker_status | name | Время попытки и короткая ошибка последнего обновления |

Общие Fire/Now имеют profile_id='*'. Персональные AI/archive/watch — ID профиля.
Прогноз и моя оценка не записываются в общую карточку. API пока отдаёт текущий
настроенный серверный профиль, выбора пользователя и авторизации здесь нет.
При реализации выбора пользователя потребуется переключать ID сервера/API и
пространство клиентского кэша; просто менять название профиля нельзя.
Рейтинги, жанры, платформы и формулы остаются в существующей recommender.sqlite3.
Кэш карточек используется для представления, он не заменяет эти данные.

## Получение и публикация

Фоновый поток стартует вместе с сервисом, независимо от открытия ТВ/браузера.
По умолчанию цикл раз в 900 секунд ПОСЛЕ завершения предыдущего, без наложения.
Сначала независимо публикуются общие Fire и Now; затем персональные разделы.
Для каждого раздела карточки и состав публикуются одной транзакцией. Читатель
использует одну read transaction; не видит половину нового состава.

Положительное сопоставление kp_id→карточка используется 30 дней, отрицательное
(успешный поиск без однозначного совпадения) — 6 часов. Ошибка сети не считается
отрицательным результатом. При ошибке поиска сохраняется прежняя полная группа.
Успешный пустой результат очищает группу. Возраст снимка не запрещает его показ.
Сетевой CUB запрос ограничен 8 секундами, максимум 4 поисковых запроса одновременно.
Разделы по 24 персональных карточки, Fire/Now до 30. Без истечения mapping TTL
фоновый цикл не повторяет поиск уже сопоставленных персональных карточек.

`GET /home.json` только читает SQLite; не делает внешний HTTP и не пересчитывает
рекомендации. Возвращает rows, profile_id, status, version. У rows есть kind,
results и refreshed_at. Настройки TTL относятся к фоновому обновлению, не GET.

## Клиент

На каждом запуске один короткий запрос по локальной сети за /home.json, timeout
1200 мс. Это чтение готового кэша, а не команда обновить его. Параллельно можно
показать прежние локальные группы. Новые снимки сохраняются для следующего
открытия. Клиент не запускает resolveAll/search для подготовки главной.
Локальный кэш `roman_home_shelves_v2` переживает перезапуск приложения; прежний
v1 используется как миграционный источник. Ошибка запроса не создаёт пустую
группу и не затирает старую. Срок снимка не блокирует показ.

При самом первом открытии нового клиента сервер может ещё готовить первую
выдачу. Continue и Fire не ждут AI. Готовые ряды могут появиться первыми; после
прогрева кэша действует обычный порядок Continue → AI → Fire → Now → Archive
→ Watch. Поздние снимки сохраняются и используются при следующем открытии.
Время первого прогрева зависит от сети и источника; обещания «всегда за N мс» нет.
Изображения по-прежнему загружаются с адресов постеров; кэш содержит их ссылки,
а не сами картинки. Загрузка постеров и работа прочих плагинов отдельно от групп.

Плашки получают сохранённые метаданные через card-ratings?cached=1: этот режим
не запускает externalids, загрузку Кинопоиска/Википедии и refresh. Нет данных —
нет такой плашки; исходная карточка остаётся доступной. Обычный режим endpoint
сохраняется для явно инициированных запросов вне главной. При частично заполненной
базе показываются имеющиеся данные, метаданные продолжают обогащаться своим потоком.

## Необязательный Кинопоиск

Вход в браузере на kinopoisk.ru не нужен: эта интеграция читает публичный профиль.
Если его нет, закрыт или не доступен: Fire/Now независимы; готовые прежние
персональные ряды сохраняются; ошибка profile видна в status. Новая установка
без профиля не показывает выдуманные персональные прогнозы и подборки.
Для полного отключения KP используйте kinopoisk_enabled=false в конфиге:
не стартуют sync/enrichment потоки. CUB-кэш продолжает работать.

Скопировать HOME_CACHE_CONFIG.example.json в data/home-cache-config.json,
изменить нужные поля, перезапустить контейнер. Для текущей установки это не нужно.
refresh_seconds: по умолчанию 900, минимум 60. cub_base_url: пустая строка означает
LAMPAC_URL + /cub/tmdb.cub.best/. Можно указать другое рабочее зеркало/прокси.
Конфиг не содержит аккаунты/пароли. Переменные HOME_CUB_BASE_URL,
HOME_REFRESH_SECONDS, KINOPOISK_ENABLED при явной установке имеют приоритет.

## Проверка

```fish
curl -fsS http://127.0.0.1:9120/home.json | jq '{profile_id, groups: [.rows[] | {kind, count: (.results|length), refreshed_at}], status}'
docker logs --tail 30 kinopoisk-sync
```

Автотесты проверяют перезапуск кэша, чтение без fetch, сохранение старых групп
при сбое, отсутствие переноса данных профиля в общие карточки, отсутствие KP,
negative TTL, порядок рядов и быстрый Continue при зависшем серверном снимке.
Прямой физический ТВ тест выполняет пользователь после установки.
