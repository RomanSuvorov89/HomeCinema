# TV update 0.5.4 — 2026-09-30

## Что изменено

- `install.py` встраивает client-defaults.js, kinopoisk.js и track-memory.js прямо
  в серверный lampainit.js. Запуск ждёт доступности API Lampa, а не appready.
  Собственный плагин остаётся в списке расширений, но его повторная загрузка
  через Lampa.Utils пропускается после успешного запуска встроенной копии.
- Предыдущий блок client-defaults внутри start() удаляется при миграции.
  Изменение идемпотентно, сохраняет остальные плагины, резервную копию и inode
  файла (важно для Docker bind mount).
- На Android ожидание одного скрипта в Utils.putScriptAsync/putScript ограничено
  6 секундами вместо штатных 60 секунд в асинхронном загрузчике. Неполученное
  расширение может отсутствовать в этом запуске; адрес записывается в журнал.
  Это ограничение НЕ является гарантией общей загрузки всей Lampa за 6 секунд:
  последовательные загрузки, другие загрузчики и сеть имеют свои сроки.
- Ошибки JavaScript и этапы запуска автоматически отправляются на сервер.
  Точная причина прежнего Script error неизвестна без стека с устройства.
- Android: internal_torrclient=true (использовать удалённый TorrServer),
  player=android, player_torrent=android. Старый выбор inner заменяется один раз.
  clearDefaultPlayer вызывается при этой миграции, если доступен. Дальше выбор
  пользователя не перезаписывается. Это включает стандартный AndroidJS.openPlayer
  в APK, а не отправку magnet в отдельный локальный торрент-клиент.
- Старые и новые API PlayerVideo проверяются перед подпиской на события дорожек.

- Внешний Android-плеер: загрузчик пропускает browser gst.js и gst/tracks.js,
  чтобы GStreamer не перехватывал MKV и не запускал серверное перекодирование
  перед открытием ViMu. Внутренний плеер и браузер сохраняют GStreamer.
  После смены режима Android → inner требуется перезапуск Lampa для его загрузки.

## Плеер и дорожки

При запуске выбрать ViMu. Если система предлагает выбор «Всегда»/«Только сейчас»,
для проверки сначала выбрать «Только сейчас». Для смены ранее запомненного
приложения использовать сброс выбора плеера в настройках Lampa.

В ViMu установить предпочтительный язык аудио Russian/Русский. При нескольких
русских озвучках конкретный дубляж может потребовать выбора вручную. Во время
воспроизведения открыть управление плеером и раздел Audio; стрелками выбрать
дорожку. Для субтитров выбрать русскую дорожку без Forced/«форсированные»/«надписи».
Полные субтитры должны реально присутствовать в файле.

Публичный API ViMu документирует внешнюю SRT-ссылку, название, позицию и плейлист,
но не документирует принудительный выбор индекса встроенной аудио/субдорожки.
Этот выпуск не обещает и не реализует перенос сохранённого выбора MPV в ViMu.
Это требует отдельной подтверждённой интеграции с конкретным Android-плеером.
Источники: https://vimu.tv/player-api/ и https://vimu.tv/documentation/.

## Проверки и границы

Автотесты: порядок CUB, ранняя выдача готового ряда, сохранение поздних рядов,
миграция Android и сохранение последующего выбора, Windows без смены плеера,
таймаут/поздний callback загрузчика, последовательная загрузка, повторная
установка и сохранение сторонних блоков, серверная диагностика без SQL.
Физический ТВ, реальная скорость 4K и поведение его списка приложений здесь
не тестировались. Обновление следует проверить на телевизоре пользователя.

## Сопровождение

После каждого изменения JS выполнять python install.py: встроенная копия
обновляется только установщиком. При следующей упаковке включать bootstrap,
все три встраиваемых JS и тесты. Не править Windows Bridge при исправлениях ТВ.
