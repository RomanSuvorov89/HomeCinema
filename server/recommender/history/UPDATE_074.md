# 0.7.4: персональный «Ещё» и ключ кеша без окна Лампы

Ошибка на скрине возникала в JSON.stringify(params) внутри кеша api.list:
params содержал ActivitySlide → Full → object → activity. Новый ключ включает
только поля запроса: url/page/query/genres/sort/language/region/method и простые
значения filter. Окно, DOM, callbacks и runtime-ссылки не сериализуются.
Кеш страниц v2 не наследует прежние ключи.

Персональный ряд «Сейчас смотрят — для тебя» допускает только карточки
с реально рассчитанным конечным прогнозом. Для CUB-карточек вне кандидатного
отчёта используется та же сохранённая модель и локальные признаки, что в
cached card-ratings. Вычисление идёт в фоне; HTTP-чтение главной не ходит в сеть.
Без нужных признаков карточка пока не попадает в персональный ряд. Отсутствие
прогноза не трактуется как плохая оценка. «Огонь» этим условием не ограничивается.

«Ещё» персонального ряда открывает roman_home_shelf, используя тот же сохранённый
ряд. По 12 карточек на страницу, стабильный снимок на время просмотра, nomore
в конце. Повторное открытие не запрашивает общий CUB-каталог. При отсутствии
локальной копии один запрос home.json читает серверный кеш. Без интеграции
Кинопоиска обычный общий «Сейчас смотрят» сохраняет стандартное раскрытие.

Клиентский кеш главной v5 исключает старые неперсональные копии.
45 Python тестов и 10 JavaScript сценариев прошли, включая циклический объект
Activity в запросе, отбор по прогнозу и раскрытие кешированного списка без сети.
