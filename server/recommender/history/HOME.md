# Изменения 0.5.3: чистый Android-клиент

- До первой Activity выбирается CUB (однократная миграция на каждом устройстве).
- На Android internal_torrclient=true: торренты идут на домашний TorrServer :8090.
- Android player/player_torrent переводятся в inner однократно: отдельный плеер
  и TorrServe не требуются для обычного браузерного сценария с серверным GStreamer.
- Windows player/MPV и запоминание дорожек не меняются.
- Вместо общего ожидания шести строк CUB выдаётся готовый упорядоченный префикс.
  Continue Watching может отображаться сразу после получения собственной истории.
- Поздние ответы удерживаются для следующих страниц, порядок не меняется на порядок
  завершения запросов. Не применяется native-рекурсия с ожиданием минимум трёх строк.
- Ожидание партии ограничено 1800 мс. Если следующий по порядку источник ещё не ответил,
  его строка не подменяется другой. Ответ сохраняется при поступлении; можно повторно
  открыть главную после восстановления связи. Само получение истории не гарантированно мгновенно.
- Сопоставление карточек использует CUB; каждый поиск ограничен 5 секундами.
- review.json запрашивается через Lampa.Reguest с таймаутом 8 секунд, без зависимости
  от fetch в старых Android WebView.

Проверены реальный upstream-контракт главной и тестовые Android Storage/Platform:
пустой и заполненный кэш, зависшие запросы, поздние ответы, порядок, скрытие строк,
миграция параметров, отсутствие правок плеера Windows. Физический ТВ не тестировался.

# Главная и рекомендации — 0.5.2

## Изменения интерфейса

Убираются строки «Последнее добавление», «В высоком качестве» и «Трейлеры».
Существующие прочие коллекции/жанры CUB остаются; эта версия не удаляет их.
Строки без результатов после фильтрации пропускаются с продолжением загрузки,
чтобы скрытый блок не обрывал прокрутку.

Порядок 0.5.1 фиксирован: «Продолжить просмотр» → «Рекомендация AI» → «Огонь!» →
«Сейчас смотрят — для тебя» → «Из прошлых лет — для тебя» → «Буду смотреть» →
прочие строки CUB. Пустые строки не создаются; отсутствие истории не создаёт
пустое «Продолжить просмотр». Кинопоиск watchlist заменяет дублирующую строку планов.

Перехват ContentRows.call ограничен синхронной сборкой main источника CUB.
Версия 0.5.2 сортирует задачи до исполнения, распознавая стандартные ключи/маршруты
CUB в callback-функциях. Запрещённые стандартные задачи не запускаются.
Дополнительная фильтрация результатов отсекает строки «Трейлеры - Новинки» и варианты.
Нет Promise.all по всему начальному набору и нет искусственного тайм-аута 15 секунд.
Используется стандартная пагинация CUB по шесть задач, без принудительной выкачки
дальних жанров и подборок. Служебная строка людей откладывается до выдачи шести
приоритетных строк, чтобы не разрывать согласованный порядок.

Полки ai/archive/watch/now/fire сохраняются отдельно в Lampa.Storage
roman_home_shelves_v1. При открытии кэш возвращается синхронно, включая после
перезапуска браузера. Кэш старше 60 секунд обновляется в фоне; результат фона
используется при следующем открытии главной, текущая прокрутка не сбрасывается.
Ошибка сети не стирает прошлую полку; успешный пустой ответ очищает её.
Если данных ещё никогда не было, первый запуск требует обычной загрузки полок.
Отрицательный результат без прошлого кэша хранится как пустой, чтобы следующий
запуск не блокировался тем же неработающим источником. Повторная попытка — спустя 60 с.
История продолжения читается стандартной задачей Lampa, не замораживается в кэше.

На старых версиях без ContentRows доступны фильтрация/сортировка каждой партии,
без гарантии глобального порядка и внедрения собственных полок. Основной путь
проверен с upstream-функциями актуального CUB; живой клиент пользователя недоступен.
Для «Ещё» поддержаны собственные маршруты recent/archive/watchlist.
В полном списке рекомендаций есть фильтр периода; сброс показывает все годы.

«Сейчас смотрят» — серверная выдача CUB, не расписание эпизодов и не гарантированная
статистика числа просмотров. Её исходный порядок используется как внешний сигнал:
base = 1 - 0.25 * position / N (position начинается с нуля).
При известном прогнозе base умножается на clamp(1 + 0.12*(prediction-6), 0.7, 1.3).
Для сериала с известной личной оценкой применяется дополнительный коэффициент 1.12.
Сведения берутся из загруженного отчёта и кэша карточек: при первом заходе данных
может не хватать; следующая загрузка главной использует пополненный кэш.
Это не персональная фильтрация всего каталога CUB, а пересортировка полученного списка.
Отдельная строка «Сейчас выходят» для знакомых сериалов с новыми эпизодами
в эту версию главной не добавлена. Не следует подменять её «Сейчас смотрят».

## Качество

Фильтр смотрит release_quality/quality. Исключает TS, HDTS, CAM/CAMRip/HDCAM,
TC, Telecine/Telesync, Screener/DVDSCR, Workprint, VHSRip.
WEB-DL, WEBRip, BluRay/BDRip/BRRip, DVDRip, HDTV разрешены. Если метка явно содержит
и допустимый релиз, и TS, карточка сохраняется. Неизвестное качество тоже сохраняется.
Фильтр применяется к данным строк главной, спискам AI/КП и ответам get/list источников
CUB/TMDB. ТМDB обычно не предоставляет качество, поэтому один лишь поиск TMDB
не позволяет установить, что во всех источниках есть только экранка.
Это фильтр метаданных, не фоновая проверка торрентов каждого фильма и не гарантия
качества фактически выбранного файла. При обновлении отметки до WEB фильм возвращается.

## Формула v3

G = взвешенное геометрическое среднее предпочтений по жанрам/сочетаниям/формату.
T = аналогичная оценка тем, авторов, режиссёров, сетей и франшиз.
Q = clamp(0.75 + 0.05 * рейтинг КП, 0.80, 1.25).
P = 100 * G * T * Q.
Прогноз = clamp(5 + 2.5 * ln(P / 100), 1, 10).
F = 1 + 0.35 * exp(-max(0,текущий_год-год_выхода) / 3).
При неизвестном годе F=1.
M = 0.95 + 0.40 * percentile(log(1+число_оценок)), внутри типа и десятилетия кандидатов.
S = вес источника: 1.03 для топ-250, 1 для популярных.
Приоритет = P * M * S * F.

Прогноз отделён от массовости, даты и источника. Это всё ещё эвристика по
профильным предпочтениям, а не обученная и проверенная регрессия личных оценок.
Для полноценной калибровки нужен отдельный этап проверки на отложенных личных оценках.
Дата здесь годовая; для продолжающихся сериалов пока используется год начала,
не сезон. Отдельная строка старых произведений не означает понижение их прогноза.
Значения новой шкалы могут стать ниже старых: убран искусственный вклад массовости.

candidate_scores.formula_version=3. Старые строки сохраняются по своим версиям.
В reasons_json добавлены preference_score и freshness_multiplier. Первый GET
/review.json пересчитывает устаревший отчёт из локальной БД без повторной загрузки
метаданных. Профильные feature stats по-прежнему используют версию 1.

## Единые плашки

Все карточки используют один renderer. Стандартная нижняя цифра скрывается и
переносится наверх с подписью «Каталог» (vote_average) либо «CUB» (cub_hundred_rating).
КП, IMDb, МОЯ и Прогноз имеют отдельные подписи. Личная оценка целочисленная.
В «Огонь!» внизу остаётся явно подписанный символом 🔥 счётчик cub_hundred_fire.
Предварительный прогноз отдаёт общий /card-ratings.json при готовых метаданных
и наличии поддержанных профильных признаков. Для уже оценённых карточек показываем
личную оценку; при нехватке данных прогноз не выдумывается.

Платформы требуют уверенности >=0.85. Пустые определения старше суток допускают
повторную проверку. platform_corrections.json хранит подтверждённые исправления
с указанием источника. Первое: The Gentlemen, tv, 2024 → Netflix, источник
https://media.netflix.com/en/only-on-netflix/81437051. Совпадение требуется по
типу, году и оригинальному названию, поэтому фильм 2019 года не затрагивается.
Кэш рейтингов обновлён до v9. Кэш сопоставлений карточек обновлён до v2: поиск
теперь требует единственного совпадения названия и года, не берёт первый ответ
при отсутствии подходящего. Неоднозначные карточки пропускаются.

## Исправления платформ в 0.5.1

Неудачный повторный поиск не затирает сохранённую платформу с уверенностью >=0.85;
перед записью читается текущая строка БД, чтобы фоновый процесс не затёр интерактивный
результат. Подтверждённые коррекции (включая явное отсутствие платформы) имеют приоритет.
Метод и исходное доказательство сохраняются вместе. Проверка свежести выполняется вновь
не ранее чем через сутки для пустых результатов.

Добавлены адресные коррекции: Silo/tv/2023 → Apple TV+;
The Odyssey/movie/2026 → отсутствие плашки платформы (кинотеатральный фильм).
Условие — оригинальное название, год, тип. Применяются при запросе карточки.
Студия Universal не подменяется телеканалом NBC.
При поиске Wikipedia обязательны точное название без скобочного уточнения, тип infobox,
год первого выпуска из поля infobox либо совпадение IMDb при отсутствии даты.
Год в произвольном тексте и частичное совпадение заголовка недостаточны.
Кинопоиск: поля платформы берутся только из объектов конкретной карточки, не из
глобального JSON-кэша соседних рекомендаций. Общая ревизия метаданных не повышается:
полная повторная загрузка базы не запускается. Старые ошибочные платформы других
произведений не объявляются автоматически исправленными.

Регрессия интерфейса использует сохранённые upstream-функции CUB main, ContentRows.call,
Api.partNext, включая реальные партии по 6 строк; сеть и UI заменены тестовыми адаптерами.
Это проверка интеграционного контракта, а не скриншотный тест на пользовательском ТВ.

## Регрессия скорости 0.5.2

Тест повторно устанавливает плагин с JSON-кэшем (аналог перезагрузки страницы),
искусственно старит его, навсегда задерживает ответы CUB now/fire, review и watchlist.
Первый набор строк с сохранёнными полками приходит менее чем за 250 мс в тестовой
среде. Это проверка отсутствия ожидания фоновых запросов, а не обещание времени
отрисовки на реальном ТВ. Проверены порядок через границу страниц и отсутствие
дублей. В первом запуске с пустым новым кэшем сетевое время остаётся.
