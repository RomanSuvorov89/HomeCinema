# 0.7.0: выходящие сериалы, калибровка и «Ещё»

## Продолжить просмотр

Используются user_ratings → series_tracking → media → identity_links → cards.
Отбирается только текущий профиль: есть личная оценка, TV, состояние airing,
режим не muted и подтверждённая дата серии от сегодня−30 до сегодня+45 дней.
Последняя вышедшая серия учитывается только до сегодняшней даты.
Это окно отражает существующую настройку ACTIVE_RECENT_DAYS/ACTIVE_NEXT_DAYS.

Сервер готовит дополнительный ряд continue в home-cache.sqlite3. Клиент объединяет
его с родным «Продолжить просмотр», оставляет реальные позиции впереди и удаляет
дубликаты по KP ID или идентификатору карточки/типу. История, закладки и таймкоды
не записываются: личная оценка не доказывает просмотр конкретной серии.
Если родного ряда нет, создаётся ряд из выходящих сериалов.

Дата не выдумывается по году сериала. Если на Кинопоиске нет расписания или карточка
ещё не сопоставлена с CUB, сериал не появится. Проверять series_tracking и /home.json.
Фоновые обновления метаданных сериалов действуют как ранее; открытие главной их не запускает.
При пустом клиентском кэше настоящая история показывается сразу; новый дополнительный
снимок сохраняется для следующего открытия. При тёплом кэше объединение мгновенное.

## Прогноз: версия формулы 4

Раньше: 5 + 2.5 × ln(preference_score / 100), независимо от шкалы пользователя.
Теперь перевод в баллы обучается на реальных оценках профиля с готовыми метаданными.
Базовые genre/theme/quality множители сохранены; массовость и свежесть влияют только
на final_score и порядок выдачи, не на персональную оценку.

Для каждой оценённой карточки из статистики каждого признака вычитается её собственный
вклад: effective'=effective−weight; utility_sum'=mean_utility×effective−utility×weight.
Affinity'=clip(1 + .65 × utility_sum' / (effective' + K), .35, 1.8).
Это устраняет прямую утечку её оценки в её обучающий признак. K совпадает с калибровкой
profile_feature_stats, перечислен в candidate_engine.FEATURE_K.

x=ln(preference_score/100). По обучающим парам (x, личная оценка):

- slope=clip(cov(x,y)/(var(x)+.001),0,12);
- prediction=clip(mean(y)+slope×(x−mean(x)),1,10);
- менее 20 полезных примеров: slope=0, показывается среднее профиля;
- нет примеров с признаками, но есть оценки с метаданными: среднее этих оценок;
- нет профиля: прогноз остаётся некалиброванным, повышенные числа не обещаются.

Новые высокие оценки должны следовать из данных, а не принудительной надбавки.
Слабые/одинаковые признаки могут оставить узкий диапазон — это честное ограничение
модели. У ожидаемого фильма с неполными метаданными прогноз тоже предварительный.

Таблица prediction_calibration(profile_id PK, model_json TEXT, calculated_at INTEGER)
создаётся автоматически в основной БД. Модель пересчитывается в фоне при расчёте
рекомендаций; /card-ratings читает сохранённую модель. /prediction-calibration.json
отдаёт параметры и диагностические ошибки MAE при достаточном числе примеров.
Каждый пятый пример отложен при проверке перевода в баллы. Это не полноценная
проверка на будущих фильмах: статистика других оценённых картин общая.
Оценивать качество по сравнению validation_mae и baseline_mae и обратной связи пользователя.

## Кэш «Ещё»

review_snapshots в home-cache.sqlite3:
profile_id PK, revision TEXT, payload_json TEXT, refreshed_at INTEGER.
Полный список оценённых кандидатов и доступные карточки записываются фоновым Builder.
Карточки общие; профильные оценки/предсказания принадлежат элементам списка.
Первый снимок публикуется до прогрева новых идентификаторов; каждые 12 обработанных
обновляется. До 60 новых сопоставлений за цикл, 4 параллельных запроса, до 8 сек каждый.
Если очередь больше, следующий цикл через 60 сек; после прогрева — штатные 900 сек.
Положительное соответствие хранится 30 дней, отрицательное — 6 часов.

/review-cached.json только читает SQLite. ?revision=... при совпадении отдаёт маленький
ответ unchanged=true; никакого пересчёта, поиска или внешнего запроса на этом HTTP пути.
Ревизия — SHA256 содержимого, первые 20 символов, не время запроса.

Клиент roman_review_snapshot_v4 показывает сохранённый список сразу и в фоне сравнивает
ревизию. Изменившийся снимок используется при следующем открытии. Фильтры/сортировка/
пагинация по 12 карточек применяются к сохранённому списку локально. Новые несопоставленные
карточки допускают прежний поиск только при первом открытии; успешные результаты
сохраняются в roman_kinopoisk_cards_v2. Сервер постепенно заполняет их независимо от клиента.

CUB/TMDB list (кроме поиска) дополнительно сохраняет до 160 страниц в
roman_catalog_pages_v1: ключ source+параметры, data JSON, at timestamp.
При повторном входе страница показывается сразу. На новом запуске одна фоновая проверка
страницы обновляет её для следующего входа; в том же запуске повторных запросов нет.
Ошибка сети не стирает старые данные. При отсутствии кэша действует обычная загрузка.
Это покрывает родные «Ещё» в Огонь/Сейчас смотрят и других списках.

Старые данные не заменяются пустотой при недоступности сервисов. Без интеграции KP
остаются родные и общие разделы CUB, без персональной калибровки.

## Проверки

Python: схема/перезапуск/offline/изоляция профилей/ревизии, выходящие серии и отсутствие
фиктивных таймкодов, стабильность калибровки и вычитание собственной оценки.
JS: родной CUB, порядок главной, объединение/дедупликация сериалов, моментальный первый
Continue, сохранённые «Ещё», изменение ревизии в фоне, страницы без повторных запросов.
Физический ТВ и реальная база профиля недоступны в среде сборки.
