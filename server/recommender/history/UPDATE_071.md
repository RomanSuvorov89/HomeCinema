# 0.7.1: расписания Кинопоиска и индикатор подгрузки

## Подтверждённая недоработка

0.7.0 искал episodes в JSON основной страницы, но не запрашивал отдельную
/film/{kp_id}/episodes/. Основная страница может вообще не содержать даты серий.
Старый parse_date принимает ISO даты; страница расписания отображает даты словами.
На странице 5024113/episodes/ при проверке 01.10.2026 опубликованы 19 эпизодов,
следующая дата — 02.10.2026. Это данные Кинопоиска, доступность видеорелиза не проверяется.

episode_schedule.py читает только видимый HTML, отслеживает «Сезон N», «Эпизод N»
и русские даты. Скрипты/стили не рассматриваются как расписание. Пустой ответ,
SSO-переход или CAPTCHA не заменяют сохранённые даты пустым массивом.
Фоновый запрос использует существующий публичный SSO bootstrap Кинопоиска и cookie jar,
персональные логин/пароль не добавляются. Защитные проверки сайта не обходятся.

episode_schedules в recommender.sqlite3:
kp_id PK/FK media, episodes_json TEXT, checked_at INTEGER, attempted_at INTEGER,
error TEXT. Даты общие, состояние series_tracking и выбор для Continue — по профилю.
Успешный кэш 6 часов; после ошибки повтор не ранее 15 минут; старая копия сохраняется.
Ограничение 12 сериалов за цикл, два параллельных запроса, тот же общий ограничитель
частоты KP; каждый запрос страницы до 8 сек после SSO. Инициализация SSO использует
существующие ограничения curl проекта и может занять дополнительное время.
Пока очередь длинная — цикл не реже 60 сек после завершения; затем штатные 900 сек.
Без KP запросы расписаний не запускаются.

Только рейтинговые TV текущего профиля и явно указанные episode_priority_ids.
Наличие валидных сезонов и серий подтверждает TV даже при прежней ошибке типа movie.
Импорт оценок распознаёт «сериал» в названии, а последующее обновление профиля сохраняет
уже подтверждённый TV-тип. Никаких фиктивных рейтингов, таймкодов или отметок просмотра.
Известные статусы завершения/отмены сохраняются при расчёте состояния расписания.

Пересчёт series_tracking по сохранённым датам выполняется каждый цикл, даже без сети.
Ряд Continue после этого строится прежним механизмом 0.7.0; при чистом клиентском кэше
первая копия записывается для следующего открытия главной.

prioritize_episodes.py принимает KP IDs, дописывает episode_priority_ids в существующий
локальный data/home-cache-config.json, сохраняет другие настройки. Приоритет ускоряет
проверку, но не добавляет сериал без оценки владельца или без подтверждённых дат.

## Индикатор

Клиент декорирует InteractionCategory для обычных разделов и AI «Ещё».
При запросе следующей страницы добавляет .roman-loading-tail после области карточек.
Имеющиеся карточки остаются; native loading при наличии карточек заменяется индикатором
в конце списка. Первая загрузка сохраняет родной механизм. Успех, ошибка и уничтожение
компонента убирают индикатор. Переопределённые после конструктора методы AI тоже учитываются.
Фоновые обновления готового кэша не показывают индикатор: пользователь их не ждёт.
Главная при ожидающих запросах ряда добавляет индикатор в конец активной области.
Физический ТВ недоступен; проверены контракты компонента, очистка и родной CUB.
